# brainstorm

把尚未稳定的问题收敛为足以决策或执行的方向。它是一项按需能力，不是新任务的前置步骤。

## 工作方式

1. 先读取与问题直接相关的上下文，区分已知事实、合理假设和真正未知项。
2. 只追问会改变目标、验收、范围、权限或关键取舍的问题；可以安全采用的可逆细节直接说明假设后继续。
3. 只有存在真实分叉时才比较 2–3 个方案。说明各自收益、代价、风险、可逆性和最强反方理由。
4. 给出明确推荐，并说明什么新证据会改变推荐。

## 输出

默认直接返回结论、关键取舍、推荐和仍需决定的事项。只有用户要求文档或后续工作确实需要稳定 brief 时才落盘；不自动创建任务目录、状态板或过程日志。

不要为了显得完整而填固定字段，也不要把已明确的工程任务重新变成需求访谈。

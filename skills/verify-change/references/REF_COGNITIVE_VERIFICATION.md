# 高影响主张验证指南

仅当一个主张会实质改变验收或风险，而且普通代码检查、测试或直接观测不足以支持时使用本指南。

## 先分类

- `routine`：通用工程检查足够，不需要本指南的完整记录。
- `domain`：需要特定领域知识、数据、工具或方法。
- `authority`：需要外部权威、资质、审计、签署或账户所有者确认。
- `judgmental`：依赖偏好与权衡，只能形成建议，不能伪装成客观证明。

## 证据要求

对 domain 或 authority 主张，记录：

- 单一、可判定的主张及其错误影响；
- 所需能力和方法；
- 实际读取的来源、版本或核实日期；
- 实际执行的工具、关键参数和结果；
- 原始证据与结论的对应关系；
- 证据未覆盖范围、残余不确定性和失效条件。

找不到匹配能力、方法无法执行或权威证据无法核实时，结论是证据不足；不得由模型自信、角色名或多个 Agent 投票补足。

## 延后验证

确实只能以后验证时，写清可观察触发条件、届时方法、所需数据、负责人、当前缓解和成功/失败分别如何改变结论。“以后再看”不构成计划。

## 判断性问题

列出选项、判断标准、事实依据、价值取舍、可逆性、最强反方理由和推荐。明确谁拥有最终决定；建议本身不能满足客观验收。

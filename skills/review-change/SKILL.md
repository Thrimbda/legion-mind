# review-change

独立审查实际变更及其可用证据。本能力不修改代码，不要求事先存在特定计划或测试报告。

## 审查方法

1. 从原始请求、相关约束和实际 diff 重建预期行为。
2. 检查 correctness、边界条件、错误处理、兼容性、维护性和范围合规。
3. 核对测试或运行证据是否真正覆盖关键主张；必要时执行有界、只读或无副作用检查。
4. 命中 auth、permission、identity、secret、签名、隐私、租户隔离或特权输入路径时展开安全视角。
5. 不把风格偏好包装成 blocker，也不把缺少理想测试自动等同于实现错误。

## 输出

先给 findings，按严重度排序。每项包含定位、原因、影响和最小修复方向；没有 actionable finding 时明确说明。随后给范围结论、证据限制和残余风险。用户要求审查文件时才落盘，不使用固定 handoff 或阶段返回规则。

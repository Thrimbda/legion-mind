# review-rfc

对现有设计做只读、证据导向的独立审查。不要替作者重写整份设计。

## 审查重点

- 目标、范围和成功标准是否一致；
- 关键假设是否有事实支持；
- 接口、状态、失败路径和并发边界是否完整；
- alternatives 是否真实，取舍是否与约束对应；
- migration、rollback、observability 与 verification 是否可执行；
- 安全、数据或外部协议风险是否被准确处理；
- 非显然主张是否有与其强度匹配的证据。

只有会导致设计不可实施、不可验证、不可回滚或产生重大风险的问题才列为 blocker。清晰度、风格和未来优化放在非阻塞建议中。

## 输出

先列按严重度排序的 findings，每项包含精确定位、原因、影响和最小修复方向；再给总体就绪判断、残余风险和建议下一步。用户要求文件时写入指定位置，否则直接回复。不要求固定 Verdict、attention 摘要或阶段交接格式。

# 工程文档检查清单

## 内容

- 开头是否说明结论、读者和用途？
- 目标、范围和非目标是否互相一致？
- 事实、推断、假设、建议和未验证内容是否可区分？
- 关键决定是否写明理由、取舍和失效条件？
- 风险是否说明影响、触发条件和缓解，而不是只列名称？
- 验证结论是否链接到真实执行结果或可重查来源？
- 文档是否重复了代码、日志或其他真源中已经清楚存在的内容？

## 结构

- 使用读者能扫描的标题和短段落；
- 将细节放到最接近其用途的位置；
- 只有确实需要时才增加附录、矩阵或时间线；
- 路径、命令、字段和错误原文保持可识别；
- 遵循仓库既有语言与命名约定。

## 状态与安全

- 不把计划、测试、UI 标签、PR 或服务存活误写成生产行为证明；
- 不把历史快照写成当前事实；
- 不持久化 secret、token、个人数据或不应扩散的内部信息；
- 没有长期价值的过程噪音不进入文档。

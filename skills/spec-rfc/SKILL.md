# spec-rfc

为一个具体技术问题形成足以实施和评审的设计。可以从用户请求、issue、现有文档或代码事实直接开始，不要求特定任务系统或前置文件。

## 方法

1. 核对目标、成功标准、范围和现有系统事实；缺失信息只有在会改变设计时才提问。
2. 描述推荐设计的边界、接口、数据流、失败行为和兼容影响。
3. 对真实备选方案说明取舍；没有真实分叉时不要虚构 alternatives。
4. 按风险补充迁移、回滚、可观测性、安全和验证设计。
5. 将事实、假设、建议和未验证主张分开。涉及领域或权威证据时，可按需读取 `../verify-change/references/REF_COGNITIVE_VERIFICATION.md`。

## 产物

用户指定路径时写入该路径；否则优先在回复中交付，或在仓库既有文档约定下选择清晰位置。结构按问题需要组织，不强制 profile、阶段状态、固定标题或伴随台账。

可按需使用 `references/REF_RFC_PROFILES.md` 选择文档深度，以及相应模板作为起点。模板是写作帮助，不是合规门。

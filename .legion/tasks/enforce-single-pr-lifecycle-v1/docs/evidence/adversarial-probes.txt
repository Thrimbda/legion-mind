Interpretation:
- A brand-new task is bound to exactly one PR and starts in open state.

  cannot invoke the repository worker.
- An ambiguous legacy binding backfills to unknown; the worker is rejected before
  launch. Only tracker observation of the same bound PR as open changes it to open,
  after which work may resume on that same PR identity.

3. Merged PR with missing repository evidence
---------------------------------------------
Observed:
{
  "terminal": {
    "decision": "terminal_non_success",
    "terminalKind": "run_terminal_non_success",
    "runState": "failed",
    "failureType": "legion_evidence_missing",
    "deliveryGate": "failed",
    "evidenceStatus": "missing",
    "locksHeld": 0,
    "blockerSatisfied": false,
    "downstreamEvent": false,
    "finalResponse": true,
    "comment": true
  },
  "sameTaskRetry": {
    "bindingState": "merged",
    "launched": false,
    "outcome": "launch_failed"
  }
}

Interpretation:
- Missing repository evidence after merge is a final non-success state.
- Locks are released, but the blocker is not satisfied and no downstream event is
  emitted.
- The terminal result is surfaced through a final response and comment.
- The original task remains bound to the merged PR and cannot launch repair work or
  create another PR. Recovery requires a user-created new task.

Probe conclusion
----------------
Both former blockers are closed under active counterexample testing. No observed
path allows the original task to launch repository work after its bound PR is merged,
closed, conflicted, or still unknown.
